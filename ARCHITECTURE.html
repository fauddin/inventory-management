System Architecture

Factory Inventory Management

A three-tier demo application: a Vue 3 single-page client, a Python FastAPI REST backend, and a JSON-file data layer loaded into memory at startup. No database, no auth, intended as a local-only demo.

Data Flow

Lifecycle of a single filter change — e.g. user selects a warehouse in FilterBar.vue.

1
User interaction
A view (Dashboard, Inventory, Orders, …) reacts to a change in the shared filter refs exposed by useFilters(): selectedPeriod, selectedLocation, selectedCategory, selectedStatus.
2
Build request
getCurrentFilters() assembles a filter object; api.js converts it to URLSearchParams, skipping any value equal to 'all'.
3
HTTP call
Axios issues a GET against http://localhost:8001/api/… — e.g. /api/orders?warehouse=W1&month=Q2-2025.
4
Server-side filtering
FastAPI parses query params via the route signature, then apply_filters() chains warehouse / category / status filters and filter_by_month() handles both direct months (2025-03) and quarter aliases (Q1-2025) via QUARTER_MAP.
5
Validation & response
Result is validated against a Pydantic response_model (InventoryItem, Order, …) and serialized to JSON.
6
Reactive render
The Vue view assigns the response to a ref (allOrders, inventoryItems, …). Computed properties derive the visible data; the template re-renders automatically.
